## 整体架构

音乐涂鸦是一个**"音乐创作民主化"**项目——让零音乐基础的人也能创作出完整的音乐。

项目采用**分层架构**，核心引擎和展示层分离，可以灵活组合：

```
┌──────────────────────────────────────────────────────────────┐
│                        展示层（Presentation）                 │
│  ┌────────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │  Web 前端 Demo  │  │  Android APP │  │  硬件互动装置    │  │
│  │  (JavaScript)   │  │  (Java/Kotlin)│  │  (嵌入式)        │  │
│  └────────┬───────┘  └──────┬───────┘  └────────┬─────────┘  │
└───────────┼───────────────────┼───────────────────┼────────────┘
            │                   │                   │
            ▼                   ▼                   ▼
┌──────────────────────────────────────────────────────────────┐
│                     核心引擎层（Engine）                       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │                    MidiEditer (C++)                     │  │
│  │  量化 / 清理重复音 / 延音 / 力度 / 和弦配器              │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │                   midifile 基础库 (C++)                 │  │
│  │           MIDI 文件读写 / 事件解析 / 时间转换            │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
            │
            ▼
┌──────────────────────────────────────────────────────────────┐
│                     音频合成层（Synthesis）                    │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │  JZZ.js      │  │  FluidSynth  │  │  硬件合成器       │  │
│  │  (浏览器)     │  │  (服务器)     │  │  (嵌入式)         │  │
│  └──────────────┘  └──────────────┘  └──────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

**核心思想：引擎是通用的，壳子是多样的。**
同一个 C++ 引擎，可以编译成不同形态，跑在浏览器、手机、服务器、嵌入式设备上。

### 前端播放链路

```
用户点击琴键
    │
    ▼
  keydown 事件
    │
    ▼
```

### 前端量化流程

```
录制的原始音符数组（recordedMelody）
    │
    ▼
  调整时间基准（减去准备时间，从0开始）
    │
    ▼
  八分音符网格量化
    │  公式：quantizedTime = round(time / unitMs) * unitMs
    │  其中 unitMs = 60000 / bpm * 0.5（八分音符时长）
    │
    ▼
  生成量化后的音符数组（quantizedNotes）
    │
    ▼
  作品回放（红色高亮 + 合成器发声）
```

### 前端的优势与局限

| 优势 | 局限 |
|------|------|
| ✅ 零部署成本，打开就玩 | ❌ 量化算法简化（只有八分音符） |
| ✅ 实时响应，按下就响 | ❌ 缺少清理重复音、延音等高级处理 |
| ✅ 迭代快，改完刷新就看效果 | ❌ 只有 2 种和弦进行（C++ 版有 6 种） |
| ✅ 可以离线运行 | ❌ 不能导出 MIDI 文件 |

### MidiConventer 核心类

`MidiConventer` 是整个引擎的核心，负责把"乱弹的原始 MIDI"变成"好听的音乐"。

```cpp
class MidiConventer {
public:
    // 主入口：一键美化
    bool Convent(int track, int bpm, int chords);

    // ===== 单个处理步骤 =====
    void QuantifyTrack(int track);          // 1. 量化：对齐节拍
    void CleanChordVoiceover(int track);    // 2. 清理和弦叠音
    void CleanRecurNotes(int track);        // 3. 清理重复音（旧版）
    void CleanRecurNotesNew(int track);     // 3. 清理重复音（新版）
    void ProlongNotes(int track);           // 4. 延音处理
    void QualifyVol(int track);             // 5. 力度量化
    void SetBPM(int track, double bpm);     // 6. 设置速度

    // 文件读写
    void Write2File(std::string file_url);

private:
    // 内部工具函数
    double QuantifyEvent(MidiEvent& midievent, int unit_size, double qualify_space, int direction);
    void   CuttingNote(MidiEvent& on, MidiEvent& off);
    bool   IsChordInterior(const MidiEvent& midievent);
    bool   CheckNoteValid(const MidiEvent& on, const MidiEvent& off);
    double GetBeat(int tick);

    // 数据
    MidiFile           m_midifile;          // MIDI 文件对象
    ChordProgression   m_chord_progression; // 和弦进行配置
    int                m_duration;          // 量化最小单位（tick）
};
```

### ChordProgression 和弦系统

内置 6 种预设和弦进行，覆盖流行、爵士、蓝调等风格：

| ID | 名称 | 类型 | 和弦序列 |
|----|------|------|---------|
| 0 | C 调布鲁斯 | 蓝调 | 12 小节蓝调进行 |
| 1 | 1625 进行 | 爵士 | C - Am - F - G（爵士版，7和弦） |
| 2 | 流行进行 1 | 流行 | 1-4M7-6m7-5sus4-5 |
| 3 | 卡农进行 | 流行/经典 | C - F - Am - G |
| 4 | 小调进行 1 | 小调 | Am - G - F9 |
| 5 | 小调进行 2 | 小调 | Am - G - F - C |

每种和弦进行包含：
- 和弦的根音、类型（大三/小三/七和弦等）
- 每个和弦的拍数
- 和弦的转位配置

## 核心算法详解

### 1. 量化算法（QuantifyTrack）

**目的：把不在拍子上的音符，拉到最近的节拍网格上。**

原理：
```
节拍网格线：|    |    |    |    |    （每格是一个八分音符）
原始音符：     o      o    o    o
量化后：    o     o     o     o
```

关键参数：
- `SPECIAL_QUALIFY = 0.6` — 特殊量化阈值。前60%的位置量化到左边，后40%量化到右边。
  - 为什么不是0.5？因为人唱歌/弹琴的时候，往往会"抢拍"一点点，偏前的概率更大。
  - 0.6的意思是：如果音符落在一格的前60%位置，就对齐到左边的线；后40%才对齐到右边的线。
  - 这样量化出来的结果更符合人的直觉。

### 2. 清理重复音（CleanRecurNotes）

**目的：去掉连续重复的、很短的音符。**

场景：用户弹的时候可能手滑，按了一下马上松开又按下去——产生两个很短的重复音。

规则：
- 如果两个相同音高的音符挨得很近（小于某个阈值）
- 并且中间的间隔很短
- 就把它们合并成一个长音

### 3. 清理和弦叠音（CleanChordVoiceover）

**目的：一个和弦里不需要弹好几个音，保留最高的那个就行。**

场景：用户可能同时按了好几个键（和弦），但旋律线应该是单音的。

规则：
- 检测同一时间范围内的多个音符
- 只保留最高的那个（旋律通常是高音部）
- 去掉其他的

### 4. 延音处理（ProlongNotes）

**目的：让旋律更连贯，不要"断断续续"的。**

原理：把每个音符的结束时间往后延 0.5 拍。

为什么？因为普通人弹琴的时候，抬手太快，音都很短，听起来"干巴巴"的。稍微拉长一点，旋律就"连起来"了，更好听。

### 5. 力度量化（QualifyVol）

**目的：统一音量，不要忽大忽小。**

原理：把所有音符的力度（velocity）统一调整到一个标准值。

普通人弹琴力度不均匀，有的音重有的音轻。统一力度后，听起来更专业。

## 技术选型说明

### 为什么用 C++ 做核心引擎？

| 原因 | 说明 |
|------|------|
| **性能** | MIDI 处理对时序精度要求高（毫秒级），C++ 纳秒级精度 |
| **跨平台** | 一次编写，可以编译到 Windows/Linux/Android/iOS/Web |
| **生态** | midifile 等底层库都是 C++ 的，MIDI 处理的 C++ 生态成熟 |
| **嵌入式** | 硬件互动装置需要跑在嵌入式设备上，C++ 是唯一选择 |

### 为什么前端用 JS 而不是 WASM？

| 原因 | 说明 |
|------|------|
| **快速迭代** | JS 改完刷新就生效，WASM 每次要编译 |
| **零门槛** | 打开 HTML 就能玩，不需要加载 wasm 文件 |
| **够用** | 几十个音符的量化，JS 性能完全够用 |
| **先验证方向** | 先确认产品好不好玩，再考虑性能优化 |

### 为什么用 Flask 做后端？

- 简单轻量，适合快速原型
- Python 调用命令行程序（C++、FluidSynth、FFmpeg）很方便
- 团队熟悉 Python

### 为什么用 FluidSynth 做合成？

- 开源免费，跨平台
- 支持 SoundFont（.sf2）音色库，可以换不同的钢琴音色
- 性能好，合成速度快
